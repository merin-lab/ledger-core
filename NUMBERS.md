# NUMBERS

For each constant: where it lives, the value, why this value, and what **half** of it would break. Rule constants are in `Policy.kt`, currency precision in `Money.kt`, and build and test constants where noted. No other numeric literals drive behaviour.

## Business constants

| Constant | Value | Where | Why this value | Why not half |
|---|---|---|---|---|
| Window first day | `1` | `Policy.windowFirstDay` | The brief's Day 1. Days are 1-based so reports read like the brief. | 0.5 is not a day. 0-based would print "Day 0" and misalign every reference to E1–E10. |
| Window last day | `6` | `Policy.windowLastDay` | The brief: "Day 1 through Day 6". Interest capitalizes when this day closes. | 3 would close the window before E5–E10: no Auth-A settlement, no E7, capitalization three days early. |
| Overdraft fee | `AED 25.00` | `Policy.overdraftFee` | The brief, stated in AED at 2 dp. | 12.50 would under-charge by 37.50 over the three fees. The value is a rule from the brief, not a tuning choice. |
| Overdraft fee, BHD | *not set* | `Policy.overdraftFee` | The brief gives no BHD fee and no FX rate. Leaving it unset makes the engine raise `NO_FEE_SCHEDULE` instead of guessing. | There is nothing to halve. Setting any value would be invention (AMBIGUITIES B7). |
| Fees per account per day | at most `1` | `assessOverdraftFees` | The brief: "once per day per account". Enforced by checking `feeForDay` before booking. | — (a count; half a fee per day has no meaning) |
| Daily interest rate | `0.0004` | `Policy.dailyInterestRate` | 0.04% = 0.04 / 100 = 0.0004, applied per day. It is a `BigDecimal` from a string literal, so there is no binary floating-point error. | 0.0002 is 0.02%/day and halves every accrual (ACC-001 would earn 0.34, not 0.69). The more likely mistake is ×10 (0.004, reading 0.04% as 0.4%), which the test pinning 0.69 would catch. |
| Interest rounding | `HALF_EVEN` | `Policy.interestRounding` | Banker's rounding has no systematic upward bias when many small accruals are rounded, and it is the IEEE 754 default rounding mode. | Not numeric. HALF_UP gives the same 0.69 here because no accrual lands on an exact half-unit. |
| Authorization threshold | available ≥ `0` | `authorize()` | The brief: "at or above zero". Zero itself is allowed (tested). | Half of zero is zero. The real risk is `> 0`, which would decline an auth that takes available to exactly 0.00; a boundary test covers it. |
| AED precision | `2` | `Currency.AED` | ISO 4217: 1 dirham = 100 fils. | 1 dp couldn't represent 185.05 or the 0.09 accruals; interest would round to 0.1 steps and lose most accruals. |
| BHD precision | `3` | `Currency.BHD` | ISO 4217: 1 dinar = 1000 fils. The brief writes 0.000 and 10.000. | 1.5 dp is meaningless. 2 dp couldn't represent 3.334/3.333 or the 0.004 daily accruals: ACC-002's interest would round to 0.00 every day. |
| Instalments in E10 | `3` | `Scenario` | The brief: "three equal instalments". | 1.5 instalments cannot be booked. |
| Split remainder step | `1` minor unit | `Money.split` | The smallest amount the currency can express, so no two instalments differ by more than 0.001 BHD. | Half a minor unit is below the currency's precision, which is exactly why 10.000 / 3 cannot divide evenly (criterion 7). |

## Build and test constants

| Constant | Value | Where | Why this value | Why not half |
|---|---|---|---|---|
| Kotlin | `2.0.21` | `build.gradle.kts`, `kotlinc` | The version of the standalone compiler that actually built and ran this repo. Using the same version on the Gradle path avoids "works in one build, not the other". | "Half" doesn't apply to a version. 1.x predates the K2 compiler used here; the code uses no 2.x-only features, but it is only verified on 2.0.21. |
| JVM bytecode target | `17` | `build.gradle.kts` | The oldest LTS JDK that recent Android Studio releases ship as their bundled runtime, so the project opens with no extra JDK install. Nothing in the code needs a newer JDK. | Target 8 would also compile, but gains nothing and invites "inconsistent JVM target" errors between Java and Kotlin tasks. |
| Gradle wrapper | `8.14.3` | `gradle/wrapper/gradle-wrapper.properties` | The Gradle installed on the build machine, so the wrapper script was generated by the same version it pins. | A version number is not a quantity. |
| Split test range | 0..2000 minor units × 1..7 parts | `Suite.kt` | Covers every remainder class for up to 7 parts hundreds of times over (14,007 cases, milliseconds). 7 is the largest instalment count I'd expect for a monthly-to-weekly split. | Half (0..1000 × 1..3) would still pass but would not test divisors 4–7, where `remainder` can reach 6. A range that small checks less than it appears to. |
| Report width | `78` columns | `Report.kt` | Fits an 80-column terminal with a 2-column margin, so the report doesn't wrap in a default console or the Android Studio Run pane. | 39 would wrap every balance line. |
